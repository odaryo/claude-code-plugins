# Codex CLI 呼び出し

Codex は独立レビュアーとして呼び出す。レビューは読み取りのみのため常に read-only サンドボックスで実行する。

## 共通: モデル判定と実行

`~/.codex/config.toml` の `model` を使う（`-codex` サフィックスは除去）。見つからなければ `-m` を省略して CLI デフォルトを使う:

```bash
MODEL=$(grep '^model[[:space:]]*=' ~/.codex/config.toml 2>/dev/null \
  | sed -nE 's/model[[:space:]]*=[[:space:]]*"([^"]+)".*/\1/p' | head -1 || true) \
  && MODEL=${MODEL%-codex} \
  && if [ -n "$MODEL" ]; then
       printf '%s' "<プロンプト>" | codex exec -s read-only -m "$MODEL"
     else
       printf '%s' "<プロンプト>" | codex exec -s read-only
     fi
```

- 実行後、出力から `session id: <UUID>` を抽出して `state.codex_session_id` に保存する
- 同一 run 内の2回目以降は文脈維持のため resume を使う（`-s` オプションなし、stdin は `-` 指定、失敗時は新規実行にフォールバック）:

```bash
(printf '%s' "<プロンプト>" | codex exec resume <session-id> - 2>&1) \
  || (echo "---FALLBACK:new---" && printf '%s' "<プロンプト>" | codex exec -s read-only 2>&1)
```

- `---FALLBACK:new---` が出力されたら新セッションになったので `state.codex_session_id` を更新する
- プロンプト内の特殊文字（`"`, `$`, `` ` ``, `\`）は適切にエスケープする。diff やファイル内容は `cat` で stdin に連結してもよい

## 出力契約（全レビュー共通）

すべてのレビュー依頼プロンプトに以下を含めること:

```
## レビュー観点
- 要件充足 / 恒久対応か（その場しのぎでないか）/ 過剰作業がないか / 漏れがないか

## 出力制約
- 冒頭に【懸念なし】または【懸念あり】を明示
- 指摘は以下の JSON 配列で出力（最大10件、重大度の高い順）
  [{"severity": "Critical|High|Medium|Low",
    "file": "対象ファイルパス", "line": 行番号,
    "evidence": "問題の根拠（コード断片・挙動）",
    "required_fix": "そのまま着手できる具体的な修正手順"}]
- required_fix は修正担当（別エージェント）がコンテキストなしで実行できる詳細度で書く
```

受領後、JSON 部分を抽出して `<run-dir>/reviews/<phase>-<連番>.json` に保存する。JSON が壊れていたら1回だけ再依頼し、それでも壊れていればテキストのまま保存して自分で構造化する。

## プロンプトテンプレート

### テストレビュー（P4 レビュー①）

```
あなたは厳格なテストレビュアーです。TDD の Red フェーズで書かれた以下のテストをレビューしてください。
実装はまだ存在しない前提です（テストが失敗するのは正常）。

## 対象機能と要件
<機能 F<n> の説明と対応する要件>

## テストコード
<テストファイルの内容>

## 確認事項
- 要件のカバレッジ（不足している観点・境界値・異常系）
- テストとして成立しているか（実装詳細への過度な依存、false positive の余地）
- テストの意図の明確さ

<共通の出力契約>
```

### 実装レビュー（P4 レビュー②）

```
あなたは厳格なコードレビュアーです。TDD サイクル（Red-Green-Refactor）完了後の実装をレビューしてください。

## 対象機能と要件
<機能 F<n> の説明と対応する要件>

## 変更内容
<git diff の内容>

## テスト結果
<テスト実行結果サマリ>

<共通の出力契約>
```

### PR レビュー（P6 独立レビュー）

```
あなたは独立した PR レビュアーです。以下の PR を要件に照らしてレビューしてください。

## PR
<PR タイトル・本文・要件チェックリスト>

## diff
<PR の full diff（大きい場合はファイル単位で分割）>

<共通の出力契約>
```

### 相互評価（P6）

```
別のレビュアー（Claude）が同じ PR に対して以下の所見を出しました。
あなた自身のレビュー結果と突き合わせて、各指摘への賛否と根拠、見落としの補足を述べてください。

## Claude の所見
<Claude の findings JSON>

## 出力制約
- 各指摘に対し agree / disagree と根拠を1-2文で
- 双方が見落としている観点があれば追加指摘（構造化形式で）
```

## エラー対応

| 事象 | 対応 |
|------|------|
| `command not found: codex` / 認証エラー | レビューをスキップせず blocked。インストール / `codex login` を案内 |
| resume 失敗 | フォールバックで新規セッション実行（上記コマンドに組込済み）。session_id を更新 |
| タイムアウト | diff を分割して再依頼。2回失敗したら blocked |
